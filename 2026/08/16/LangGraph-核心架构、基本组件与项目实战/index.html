一、LangGraph 核心架构

LangGraph 是 LangChain 生态中用于构建有状态、可循环、可控制、支持持久化的 AI Agent（智能体）应用的核心框架。

如果说 LangChain 主要解决如何调用大模型、组织 Prompt、连接工具，那么 LangGraph 进一步解决：

  • 如何让 AI 按照业务流程执行任务？
  • 如何让 AI 根据执行结果自主决定下一步？
  • 如何实现多轮对话和上下文状态管理？
  • 如何让 Agent 在执行过程中调用外部工具？
  • 如何实现人工审核、暂停、恢复和长期记忆？
  • 如何构建多个 Agent 协同工作的系统？

一句话理解：LangGraph 通过图结构，把大模型、工具、业务逻辑和状态管理组织成一个可运行的智能体工作流。

1.1 整体架构

LangGraph 的核心设计思想是 Graph（图）。它将 AI 应用拆分成多个节点（Node），节点之间通过边（Edge）连接，利用 State（状态）传递上下文信息。

1.2 核心运行机制

LangGraph 可以看作一个状态驱动的图执行引擎：

  1. 接收用户输入。
  2. 初始化 Graph State。
  3. 根据入口边找到第一个 Node。
  4. Node 执行对应业务逻辑。
  5. Node 返回状态更新。
  6. Graph 根据 Edge 决定下一个执行节点。
  7. 重复执行，直到到达 END。

LangGraph 的特点是支持循环、分支、并行、暂停、恢复和动态路由。

1.3 底层执行模型

LangGraph 的 Graph API 采用类似 Google Pregel 的消息传递和 Super-step（超级步）执行模型。

Super-step 一轮节点调度和执行
Halt 所有节点完成且没有待处理消息时结束

二、LangGraph 基本组件详解

2.1 State：状态管理

State 是整个 Graph 的共享状态容器，保存 Agent 执行过程中需要使用的数据，例如用户输入、历史对话、当前执行步骤、工具调用结果、用户身份和业务处理结果。

LangGraph 会根据字段对应的更新规则合并节点返回值。节点不必每次返回完整 State。

Reducer：状态合并器

Reducer 决定多个节点更新同一个 State 字段时如何合并。默认情况下，字段更新通常采用覆盖策略。

这里的 operator.add 表示列表追加合并。在实际 Agent 中，消息列表通常使用 LangGraph 提供的 add_messages Reducer，以正确处理消息 ID 和更新。

2.2 Node：节点

Node 是 Graph 的基本执行单元。本质上通常是一个 Python 函数，可以调用大模型、查询数据库、调用第三方 API、执行 Python 业务逻辑或处理工具返回结果。

2.3 Edge：边

Edge 用来定义节点之间的执行关系。

普通边：add_edge

表示分类完成后执行查询。

条件边：add_conditional_edges

入口和出口

  • START：图执行入口。
  • END：图执行终点。

2.4 StateGraph：图构建器

StateGraph 是构建 LangGraph 应用的主要类。

API 作用
StateGraph() 定义图及状态结构
add_node() 添加节点
add_edge() 添加普通边
add_conditional_edges() 添加条件边
compile() 编译图，生成可执行应用

2.5 Tool：工具调用

Tool 是 Agent 连接外部系统的能力接口，例如查询订单、查询商品库存、搜索互联网、查询天气、发送邮件和查询企业内部数据库。

大模型可以根据用户问题决定是否调用工具。

区别： Tool 是可供模型调用的能力；Node 是图执行单元。Tool 可以被 ToolNode 执行，也可以在普通 Node 中调用。

2.6 ToolNode 和 tools_condition

  • ToolNode：负责执行模型发出的工具调用。
  • tools_condition：根据模型输出判断是否存在工具调用，并决定继续执行工具节点还是结束。

2.7 Checkpointer：持久化与记忆

Checkpointer 保存 Graph 执行过程中的状态快照。

例如用户先问“我想查询订单 10001”，之后问“预计什么时候到？”。如果会话状态得到保存，Agent 就可以在同一会话中理解第二个问题指向前面的订单。

使用 Checkpointer 时，通常通过 thread_id 区分会话。

类型 用途
InMemorySaver 开发测试，进程内保存
SQLite Checkpointer 本地开发、小型应用
PostgresSaver 生产环境持久化

注意：内存 Checkpointer 在服务进程重启后会丢失状态，不适合生产环境。

2.8 Interrupt：人工介入

Interrupt 允许 Agent 暂停执行，等待人工确认后再恢复。

这对于资金操作、删除数据、修改业务记录等高风险操作尤其重要。

2.9 Send 和 Command

组件 主要用途
Send 动态分发任务，支持 Map-Reduce 和并行执行
Command 在节点内同时更新状态和指定下一步路由
Subgraph 将子工作流封装为可复用子图
Runtime Context 向节点传递运行时配置和依赖

例如，一篇文章需要分别生成摘要、关键词和分类，可以通过 Send 将任务分发给多个 Worker 并行执行，再整合结果。

六、最重要的知识点总结

  1. State 是数据中心：所有节点共享工作流状态。
  2. Node 是执行单元：每个节点完成一项具体任务。
  3. Edge 是控制流程：决定下一个执行什么节点。
  4. Checkpointer 是持久化机制：支持状态保存和恢复。
  5. Agent 是决策执行主体：大模型决定如何使用工具、如何完成任务。

还要区分：

  • LangChain：侧重模型、工具、检索等组件的集成。
  • LangGraph：侧重 Agent 的状态管理、执行控制和工作流编排。

两者可以结合使用，但 LangGraph 本身并不强制依赖 LangChain。
